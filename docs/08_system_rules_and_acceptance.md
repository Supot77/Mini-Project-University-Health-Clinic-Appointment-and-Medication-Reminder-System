# 08. กติการะบบและเกณฑ์ตรวจรับ

ปรับปรุง 7 กันยายน 2569 (2026-09-07) — ฉบับ scope manual ขนาดเล็กตาม D22 ใน [10](10_team_decisions.md) ยังไม่ใช่หลักฐานว่าโค้ดหรือฐานข้อมูลทำครบแล้ว

## 1. หลักการ scope

- ระบบเป็น manual-first ไม่มี automation, worker, cron, retry, catch-up, email หรือ Web Push
- ระบบไม่เปลี่ยนสถานะจากเวลาเอง ทุกการอนุมัติ ปิด slot จบตรวจ จ่ายยา และบันทึกเตือนต้องมีผู้ใช้ที่มีสิทธิ์กดคำสั่ง
- ใช้ validation พื้นฐานเพื่อป้องกันข้อมูลผิดและข้อมูลซ้ำเท่านั้น ไม่เพิ่มกฎผ่อนผันหรือเส้นตายย่อย
- Runtime ปัจจุบันใช้ mock และการทดสอบต้องไม่เรียกฐานข้อมูลจริงหรือบริการภายนอก

## 2. สิทธิ์

| บทบาท | งานหลัก | ขอบเขตจำกัด |
| --- | --- | --- |
| patient | โปรไฟล์ จองนัด ดูผลตรวจ/ยา และบันทึกผลเตือนของตน | อ่านหรือแก้ข้อมูลของคนอื่นไม่ได้ |
| staff | จัดการ slot นัด วันลา รายการเตือน และ Broadcast ตามสิทธิ์ | ไม่เห็น diagnosis และไม่จ่ายยา |
| doctor | ตรวจผู้ป่วยตามนัดของตน และบันทึกผลตรวจ | แก้ข้อมูลของแพทย์อื่นไม่ได้ |
| pharmacist | ดูรายการยาและจ่ายเต็มตามใบสั่ง | ไม่เห็น diagnosis และไม่แบ่งจ่าย/กันยา |
| admin | จัดการบัญชี role และส่ง Broadcast | ไม่มีสิทธิ์งานคลินิกโดยอัตโนมัติ |

## 3. กติกาการทำงาน

- Staff กรอก slot เอง ตรวจไม่ให้เวลาทับกัน และปิด slot เองเมื่อจำเป็น
- Patient จอง slot ที่ว่างเป็น `pending`; Staff อนุมัติหรือปฏิเสธด้วยมือ
- Staff และ Doctor เปลี่ยนสถานะการตรวจด้วยมือ; Doctor จบตรวจได้เมื่อบันทึกผลตรวจแล้ว
- หากแพทย์ลา Staff ปิด slot และติดต่อจัดการนัดเดิมทีละรายการ ไม่มีการย้ายหรือยกเลิกอัตโนมัติ
- Pharmacist จ่ายเต็มตามจำนวนที่สั่งในครั้งเดียว หากยาไม่พอให้ปฏิเสธการจ่ายและบันทึกเหตุผล
- Staff สร้างรายการเตือนจากยาที่จ่ายเต็ม ผู้ป่วยกดบันทึกผลเองในเว็บ ไม่มีการคำนวณ `missed` หรือการเตือนซ้ำ
- Admin ส่ง Broadcast เมื่อกดส่งเท่านั้น

## 4. Acceptance Criteria

| รหัส | สถานการณ์ | ผลที่ต้องได้ |
| --- | --- | --- |
| AC01 | สมัครด้วยอีเมลนอกโดเมน | ระบบปฏิเสธและไม่สร้างบัญชี |
| AC02 | ผู้ใช้เปิดข้อมูลของบัญชีอื่น | ระบบปฏิเสธทั้ง UI และ service |
| AC03 | Staff สร้าง slot เวลาทับกันหรือความจุไม่ถูกต้อง | ไม่บันทึกและแสดงข้อผิดพลาด |
| AC04 | Patient จอง slot เต็มหรือส่งคำขอซ้ำ | ไม่สร้างนัดซ้ำและจำนวนจองไม่เกินความจุ |
| AC05 | Staff อนุมัติ/ปฏิเสธนัด | สถานะเปลี่ยนตามคำสั่งและ role ที่ถูกต้อง |
| AC06 | Doctor จบตรวจโดยไม่มีผลตรวจ หรือแก้นัดของแพทย์อื่น | ระบบปฏิเสธและข้อมูลเดิมไม่เปลี่ยน |
| AC07 | Staff จัดการนัดเมื่อแพทย์ลา | เปลี่ยนเฉพาะรายการที่เลือก ไม่มี auto-cancel หรือ auto-reschedule |
| AC08 | Pharmacist จ่ายยาเมื่อ stock ไม่พอ | ปฏิเสธการจ่าย ไม่ตัด stock และแสดงเหตุผล |
| AC09 | Pharmacist จ่ายเต็มสำเร็จ | ตัด stock ตามจำนวนจริงและบันทึกผู้ทำกับเวลา |
| AC10 | Staff สร้างเตือนจากยาที่ยังไม่จ่ายเต็ม | ระบบปฏิเสธการสร้าง |
| AC11 | Patient บันทึกผลเตือนของบัญชีอื่น | ระบบปฏิเสธ |
| AC12 | Admin ส่ง Broadcast | ข้อความถูกสร้างเมื่อกดส่ง และไม่มีการส่งซ้ำตามเวลา |
| AC13 | คำสั่งใด validation ไม่ผ่าน | state เดิมไม่เปลี่ยน |
| AC14 | เปิดหน้าหลังเวลาผ่านไป | ระบบไม่เปลี่ยนสถานะนัด ยา หรือเตือนเอง |
| AC15 | ระบบทดสอบ | ไม่เรียก network, email provider, worker หรือฐานข้อมูลจริง |

## 5. เส้นทางสาธิตขั้นต่ำ

1. ผู้ป่วยสมัครและเข้าสู่ระบบ
2. Staff สร้าง slot และผู้ป่วยจอง
3. Staff อนุมัตินัด และ Doctor บันทึกผลตรวจ
4. Pharmacist จ่ายยาเต็ม และ Staff กรอกรายการเตือน
5. ผู้ป่วยเปิดรายการของตนและกดบันทึกผลด้วยมือ
6. Admin ส่ง Broadcast ด้วยมือ

ไม่มี SCN สำหรับเลื่อนนัดอัตโนมัติ แบ่งจ่าย/กันยา ยาค้าง email worker missed หรือการเตือนซ้ำ

## 6. เกณฑ์ส่งมอบ

ต้องตรวจ lint, typecheck, test และ build ตามคำสั่งใน README และตรวจ flow หลักด้วย Chrome ที่ 360px และ 1280px รวม keyboard, loading, empty และ error โดยรายงานผลจริง ไม่ถือว่าเอกสารเป็นหลักฐานว่าระบบผ่านการตรวจรับแล้ว
