# Catalog ข้อมูลเดโมคลินิกมหาวิทยาลัย

ปรับปรุง 5 กันยายน 2569 (2026-09-05) — ข้อกำหนดสำหรับพัฒนา ยังไม่ใช่หลักฐานว่าโค้ดหรือฐานข้อมูลทำครบแล้ว

เอกสารเดิมวันที่ 4 ก.ย. ปรับกติกาที่ถูกแทนตาม [ข้อสรุปทีม](../../10_team_decisions.md) คงรายชื่อสังเคราะห์ ตารางตรวจและยาเดิม ไม่ใช้แบบจ่ายครบใบ/Reminder Hybrid/Admin ทุกสิทธิ์เป็นกติกาปัจจุบัน

## 1. เป้าหมายและสถานะ

บัญชี 17 แผนก 4 แพทย์ 6 เภสัชกร 1 ผู้ป่วย 8 และยา 7 รายการ ใช้ข้อมูลแต่งเพื่อทดสอบ ไม่ได้แก้ seed หรือรัน Bootstrap ในงานนี้

## 2. ขอบเขต

รองรับนัด คิว ผลตรวจ แบ่งจ่าย/ค้าง/กันยา Staff ตั้งเตือนจากรับจริง ผู้ป่วยยืนยันเวลา Broadcast และ Dashboard ตามบทบาท ไม่รวม walk-in, Web Push, ลากวาง, หลายสาขา/เขตเวลา รายละเอียดคืนยายังรอตอบ

มี Broadcast ตัวอย่าง อ่านแล้วและยังไม่อ่าน ใช้ผู้ส่ง Admin และ Dashboard 5 บทบาทตาม [08](../../08_system_rules_and_acceptance.md) Bootstrap ไม่ส่งอีเมลจริง แต่ต้องทดสอบส่งจริงก่อนนำเสนอ สูตรตัวเลขที่กระทบจากแบ่งจ่าย/กันยารอรับรอง

## 15. หน้าจอในขอบเขตของช้อป

### หน้าจัดการแผนกและแพทย์

- แท็บแผนก: ค้นหา เพิ่ม แก้ไข ลบหรือปิดใช้งาน
- แท็บแพทย์: กรองตามแผนก เพิ่มแพทย์ กำหนดความเชี่ยวชาญ ลบหรือปิดใช้งาน
- ซ่อนรายการปิดใช้งานตามค่าเริ่มต้นและมีตัวกรองดูย้อนหลัง
- การลบหรือปิดใช้งานมีหน้าต่างยืนยันและบอกผลกระทบ

### หน้าปฏิทินตารางตรวจ

- มุมมองรายสัปดาห์เป็นค่าเริ่มต้น
- กรองตามแผนก แพทย์ และสถานะรอบ
- สร้าง ดู แก้ไข และปิดรอบ
- แสดงเวลา แพทย์ แผนก จำนวนจอง/ความจุ และสถานะ
- `available`, `full` และ `closed` ใช้สีต่างกัน
- ไม่มี Drag-and-drop ในรุ่นแรก
- มือถือใช้รายการเรียงตามวัน

หน้าจองคิวเป็นของปายและใช้รหัสแพทย์ รหัสรอบ วันเวลาไทย ความจุ สถานะ และเงื่อนไขเปิดรับจากโมดูลช้อป

## 16. Bootstrap สำหรับ Supabase ร่วม

ทีมใช้ Supabase ออนไลน์ร่วมกันหนึ่งโปรเจกต์ หัวหน้าทีมเป็นผู้ถือ `service_role` และรัน Bootstrap จากเครื่องของตน สมาชิกได้รับเฉพาะบัญชีเดโม

ลำดับ Bootstrap:

1. Auth Users
2. Profiles และ Roles
3. Departments
4. Doctors และสังกัดแผนก
5. Medications และยอดสต๊อก
6. Appointment Slots แบบวันที่สัมพันธ์กับวันรัน
7. Appointments
8. Medical Records และใบสั่งยา
9. Inventory Logs
10. Medication Reminders และ Logs
11. Notifications และข้อมูลต้นทางสำหรับ Dashboard

Bootstrap ต้อง:

- ใช้ Admin API สร้าง Auth User และยืนยันอีเมลสำหรับเดโม
- หา Auth User เดิมด้วยอีเมลและใช้ `user_id` เดิมเมื่อรันซ้ำ
- ใช้รหัสคงที่สำหรับข้อมูลธุรกิจและ `upsert` ข้อมูลเดโม
- คำนวณวันย้อนหลัง 7 วัน วันนี้ และล่วงหน้า 14 วันด้วย `Asia/Bangkok`
- เปลี่ยนเฉพาะบัญชีและรหัสเดโมที่ระบุใน Catalog
- ไม่ล้างฐานข้อมูลทั้งโปรเจกต์
- รายงานจำนวน `created`, `updated`, `skipped` และ `failed`
- ไม่แสดง Secret หรือรหัสผ่านใน Log

`service_role` เก็บใน Environment ของเครื่องหัวหน้าทีม ไม่อยู่ในโค้ดฝั่งเว็บ ไม่ commit และไม่แจกให้สมาชิก

ก่อนรัน Bootstrap หัวหน้าทีมต้องแจ้งทุกครั้ง และต้องรับรอง mapping บัญชีทดสอบตามข้อจำกัดโดเมนล่าสุด ขั้นตอนเดิมเป็นแนวทางสำหรับปรับในอนาคต ไม่ใช่สคริปต์พร้อมรองรับ schema ใหม่
