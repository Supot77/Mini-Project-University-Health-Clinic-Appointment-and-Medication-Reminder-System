# 02. Requirements และ User Stories

ปรับปรุง 7 กันยายน 2569 (2026-09-07) — ฉบับ scope manual ขนาดเล็กตาม D22 ยังไม่ใช่หลักฐานว่าโค้ดหรือฐานข้อมูลทำครบแล้ว

## บทบาทที่ใช้ในทุกโมดูล

- ผู้ป่วย (`patient`)
- แพทย์/เภสัชกร (`medical`)
- เจ้าหน้าที่/แอดมิน (`staff_admin`)

แพทย์และเภสัชกรเป็นหน้าที่ภายใต้ `medical` เดียวกัน เจ้าหน้าที่และแอดมินเป็นหน้าที่ภายใต้ `staff_admin` เดียวกัน

## ฟีม — สมาชิกและโปรไฟล์

- ผู้ป่วยนักศึกษา/บุคลากรสมัครด้วยอีเมล @mail.wu.ac.th และรหัสผ่าน ยืนยันอีเมล เข้าสู่ระบบ ออกจากระบบ และรีเซ็ตรหัสผ่านได้
- ผู้ป่วยกรอกข้อมูลบังคับตามประเภท แก้ข้อมูลส่วนตัวและประวัติสุขภาพ มี/ไม่มี/ไม่ทราบได้ โดยไม่เปลี่ยน role เอง
- เจ้าหน้าที่/แอดมินค้นหาผู้ป่วยด้วยรหัสหรือเบอร์โทร เห็นเฉพาะข้อมูลที่อนุญาต
- เจ้าหน้าที่/แอดมินสร้างและจัดการบัญชีคลินิก กำหนดสิทธิ์/ระงับบัญชีแล้ว session เดิมหมดสิทธิ์ทันที

## ช้อป — แผนกและตาราง

- เจ้าหน้าที่/แอดมินจัดการแผนก แพทย์ slot และความจุ ตรวจเวลาทับ
- เจ้าหน้าที่/แอดมินดูปฏิทิน กรองวัน/แพทย์/แผนก และกรอกหรือปิด slot ด้วยตนเอง
- ข้อมูลที่มีประวัติอ้างอิงต้องไม่ลบจนความสัมพันธ์เสีย ตามฐาน Catalog

## ปาย — นัดและผลตรวจ

- ผู้ป่วยดูเวลาว่าง จอง slot และดูสถานะ/ประวัติของตน
- เจ้าหน้าที่/แอดมินอนุมัติ/ปฏิเสธและจัดการนัดที่ได้รับผลกระทบด้วยมือ; `staff_admin` และ `medical` จัดสถานะตรวจ โดยหน้าที่แพทย์ทำเฉพาะนัดตน
- `medical` ในหน้าที่แพทย์อ่านประวัติการรักษาของผู้ป่วยที่รับผิดชอบ; `medical` ในหน้าที่เภสัชกรจัดการยา; ผู้ป่วยอ่านผลหลังจบตรวจ

## กัญจน์ — คลังและการจ่าย

- `medical` ในหน้าที่เภสัชกรเพิ่ม/แก้/ระงับยา รับเข้า/ปรับยอด ดูวันหมดอายุและประวัติคลัง; `medical` ในหน้าที่แพทย์อ่านสต๊อกได้แต่ไม่แก้ยอด
- `medical` ในหน้าที่เภสัชกรดูชื่อ ประวัติแพ้ยา ใบสั่งและประวัติจ่าย โดยไม่เห็นวินิจฉัย
- `medical` ตรวจ stock และจ่ายเต็มตามจำนวนที่สั่งในครั้งเดียว
- หากยาไม่พอ `medical` ปฏิเสธการจ่ายและบันทึกเหตุผล ไม่มีแบ่งจ่าย กันยา หรือยาค้าง

## กลอง — เตือนและประวัติมื้อ

- เจ้าหน้าที่/แอดมินกรอกรายการเตือนจากยาที่จ่ายเต็ม ผู้ป่วยกดบันทึกผลด้วยตนเอง
- ไม่มี email, worker, missed, การเตือนซ้ำ, การพักเตือน หรือเส้นตายย้อนหลัง

## เฮิร์บ — ข้อความและ Dashboard

- เฉพาะเจ้าหน้าที่/แอดมินกรอกและส่ง Broadcast ด้วยมือไปยังทุกคนหรือ role ที่เลือก
- Dashboard แสดงข้อมูลที่บันทึกแล้วตาม role ไม่คำนวณงานตามเวลาเอง

| บทบาท | Dashboard |
| --- | --- |
| เจ้าหน้าที่/แอดมิน | นัดวันนี้ คิวคงเหลือ ภาระแต่ละแผนก บัญชี และสถิติรวมที่ไม่เปิดข้อมูลผู้ป่วย |
| แพทย์/เภสัชกร | คิวของตนเมื่อเป็นแพทย์ รายการจ่าย และสต๊อกปัจจุบัน |
| ผู้ป่วย | ไม่มีสิทธิ์เข้าหน้า Dashboard; ใช้หน้านัด ยา การเตือน และกล่องข้อความของตนโดยตรง |

ทุกงานใช้สิทธิ์ตาม [08](08_system_rules_and_acceptance.md) ตรวจที่ฝั่งข้อมูลด้วย ไม่อาศัยซ่อนเมนูเพียงอย่างเดียว กติกาที่ยังไม่ครบติดตามใน [10](10_team_decisions.md)

## วิธีตีความ User Story ในเอกสารนี้

รายการด้านบนอธิบาย “ใครทำอะไรกับข้อมูลใด” ไม่ได้แปลว่าทุกหน้าต้องมี workflow แยกใหม่ หากเป็นงานของ `medical` ให้ดูหน้าที่ที่กำลังทำว่าเป็นงานแพทย์หรืองานเภสัชกร แล้วตรวจความสัมพันธ์กับนัด ผู้ป่วย และรายการยาให้ครบ ส่วน `staff_admin` รวมงานเจ้าหน้าที่กับแอดมินไว้ในบัญชีเดียว แต่ยังต้องตรวจสิทธิ์ก่อนทุกคำสั่ง

ผลลัพธ์ของทุก story มีหลักเดียวกัน: ถ้าข้อมูลและสิทธิ์ถูกต้องจึงบันทึกและแสดงผลสำเร็จ; ถ้า validation หรือ permission ไม่ผ่านต้องแสดงเหตุผลและคงข้อมูลเดิม การเปิดหน้าได้หรือการซ่อนเมนูจึงไม่ถือว่า story สำเร็จจนกว่าจะตรวจ service/data layer ด้วย

## แผนที่ผลลัพธ์ตามโมดูล

| โมดูล | ข้อมูลตั้งต้น | ผู้ทำหลัก | ผลลัพธ์ที่ตรวจได้ |
| --- | --- | --- | --- |
| สมาชิก/โปรไฟล์ | อีเมล บัญชี และข้อมูลผู้ป่วย | ฟีม | session, role และโปรไฟล์ตามประเภท |
| แผนก/ตาราง | แผนก แพทย์ วันเวลา และความจุ | ช้อป | slot ที่ไม่ทับกันและสถานะที่ผู้ใช้บันทึก |
| นัด/ผลตรวจ | slot ผู้ป่วย และผู้รับผิดชอบ | ปาย | สถานะนัด ผลตรวจ และรายการยาที่อ้างอิงกัน |
| คลัง/การจ่าย | Catalog stock และจำนวนที่สั่ง | กัญจน์ | ผลจ่ายเต็มหรือเหตุผลที่ปฏิเสธ พร้อมประวัติ |
| รายการเตือน | ยาที่จ่ายเต็มและข้อมูลผู้ป่วย | กลอง | รายการเตือนในเว็บและผลที่ผู้ป่วยกดบันทึก |
| ข้อความ/Dashboard | ข้อมูลที่โมดูลอื่นบันทึกแล้ว | เฮิร์บ | Broadcast และข้อมูลสรุปตาม role |

ตารางนี้เป็นการจัดกลุ่มเพื่ออ่าน flow เดียวกัน ไม่ได้เพิ่มตาราง ผู้ใช้ หรือความสามารถนอก scope
