# 02. Requirements และ User Stories

ปรับปรุง 5 กันยายน 2569 (2026-09-05) — ข้อกำหนดสำหรับพัฒนา ยังไม่ใช่หลักฐานว่าโค้ดหรือฐานข้อมูลทำครบแล้ว

## ฟีม — สมาชิกและโปรไฟล์

- ผู้ป่วยนักศึกษา/บุคลากรสมัครด้วยอีเมล @mail.wu.ac.th และรหัสผ่าน ยืนยันอีเมล เข้าสู่ระบบ ออกจากระบบ และรีเซ็ตรหัสผ่านได้
- ผู้ป่วยกรอกข้อมูลบังคับตามประเภท แก้ข้อมูลส่วนตัวและประวัติสุขภาพ มี/ไม่มี/ไม่ทราบได้ โดยไม่เปลี่ยน role เอง
- เจ้าหน้าที่ค้นหาผู้ป่วยด้วยรหัสหรือเบอร์โทร เห็นเฉพาะข้อมูลที่อนุญาต
- Admin สร้างและจัดการบัญชีคลินิก กำหนดสิทธิ์/ระงับบัญชีแล้ว session เดิมหมดสิทธิ์ทันที

## ช้อป — แผนกและตาราง

- เจ้าหน้าที่จัดการแผนก แพทย์ สังกัดและรอบตรวจพร้อมความจุ ตรวจเวลาทับและรอบข้ามวัน
- เจ้าหน้าที่ดูปฏิทิน กรองวัน/แพทย์/แผนก และปิดรอบเมื่อแพทย์งดตรวจโดยคงประวัตินัด
- ข้อมูลที่มีประวัติอ้างอิงต้องไม่ลบจนความสัมพันธ์เสีย ตามฐาน Catalog

## ปาย — นัดและผลตรวจ

- ผู้ป่วยดูเวลาว่าง จองล่วงหน้า 1–14 วัน ยกเลิกก่อนเริ่มอย่างน้อย 2 ชั่วโมง และดูสถานะ/ประวัติของตน
- เจ้าหน้าที่อนุมัติ/ปฏิเสธและจัดการ pending ค้าง; เจ้าหน้าที่และแพทย์จัดสถานะตรวจ โดยแพทย์ทำเฉพาะนัดตนและปิดหลังมีผลตรวจ
- เจ้าหน้าที่เสนอรอบใหม่ กันที่ทันที ให้ผู้ป่วยตอบ/เลือกวันอื่นใน 24 ชั่วโมง ไม่ตอบถือว่ายืนยัน; รอบใหม่ต้องเริ่มหลังพ้นกำหนดตอบ
- แพทย์อ่านประวัติการรักษาย้อนหลังของผู้ป่วยที่รับผิดชอบ รวมแพทย์อื่น ตรวจและสั่งยา ผู้ป่วยอ่านผล/ใบสั่งหลังปิดตรวจ
- แพทย์แก้ส่วนยาที่ยังไม่จ่ายโดยมีเหตุผลและประวัติ ให้เภสัชกรตรวจใหม่เมื่อกระทบรายการกันยา

## กัญจน์ — คลังและการจ่าย

- เภสัชกรเพิ่ม/แก้/ระงับยา รับเข้า/ปรับยอด ดูวันหมดอายุและประวัติคลัง; แพทย์อ่านสต๊อกได้แต่ไม่แก้ยอด
- เภสัชกรดูชื่อ ประวัติแพ้ยา ใบสั่งและประวัติจ่าย โดยไม่เห็นวินิจฉัย
- เภสัชกรแบ่งจ่ายตามดุลยพินิจเป็นรายยา บันทึกเหตุผล จำนวนจ่ายจริงและค้าง ตัดยอดจริงครั้งละธุรกรรม
- เภสัชกรยืนยันค้างพร้อมจ่ายและกันยา ก่อนเจ้าหน้าที่แจ้งผู้ป่วย เมื่อรับจริงบันทึกการจ่ายเพิ่ม
- เจ้าหน้าที่ยกเลิกส่วนค้างและปล่อยยาที่กันเมื่อผู้ป่วยไม่รับ โดยไม่เปลี่ยนประวัติที่จ่ายแล้ว

## กลอง — เตือนและประวัติมื้อ

- เจ้าหน้าที่สร้างเตือนจากยาที่รับจริง ผู้ป่วยเลือก/ยืนยันเวลาแล้วล็อก ไม่มีสิทธิ์สร้างยาเองหรือเปลี่ยนคำสั่งยา
- ผู้ป่วยรับอีเมลก่อน 10 นาทีและข้อความในเว็บเมื่อถึงเวลา; ยืนยันใกล้มื้อแรกไม่ถึง 10 นาทีส่งอีเมลทันที
- ผู้ป่วยเปิดลิงก์อีเมล ล็อกอินและยืนยันบันทึกในเว็บ ระบุเวลากินโดยประมาณและแก้การกดผิดได้ภายในเส้นตาย
- ระบบกำหนด missed หลัง 1 ชั่วโมง เปิดบันทึกถึง 30 นาทีหลังมื้อถัดไป; มื้อสุดท้ายเตือนซ้ำทั้งสองช่องทางหลัง 3 ชั่วโมงและปิดรับอีก 30 นาที
- ผู้ป่วยพักอีเมล 1/8/24 ชั่วโมงได้ โดยไม่กระทบในเว็บและอีเมลนัด/รับยาค้าง
- เจ้าหน้าที่ส่งข้ามพักได้ 1 ครั้งต่อมื้อรวมทุกคน เฉพาะ missed ที่ยังบันทึกได้และต้องมีเหตุผล

## เฮิร์บ — ข้อความและ Dashboard

- เฉพาะ Admin ส่ง Broadcast ได้ เลือกผู้ใช้ทุกคนหรือเลือกตามบทบาท ไม่รองรับการส่งรายบุคคล
- ตรึงรายชื่อผู้รับเมื่อส่ง ผู้รับที่ตรงหลายเงื่อนไขได้รับครั้งเดียวต่อรหัส Broadcast การเปลี่ยนบทบาทภายหลังไม่เปลี่ยนรายชื่อเดิม
- กันคำขอเดิมที่ส่งซ้ำ แต่สร้าง Broadcast ใหม่ที่ใช้ข้อความเดิมได้
- ผู้รับอ่านแล้ว/ลบได้เฉพาะกล่องตนเอง ประวัติกลางและกล่องของคนอื่นคงอยู่

| บทบาท | Dashboard |
| --- | --- |
| Staff | นัดวันนี้ คิวคงเหลือ ภาระแต่ละแผนก |
| Doctor | คิวตนเอง จำนวนตรวจเสร็จ และนัดวันนี้ของตน |
| Pharmacist | รอจ่าย ยาค้างจ่าย สต๊อกต่ำ ยาหมดอายุ |
| Admin | บัญชี สิทธิ์ สถานะระบบ สถิติรวมที่ไม่เปิดข้อมูลผู้ป่วย |
| Patient | ไม่มีสิทธิ์เข้าหน้า Dashboard; ใช้หน้านัด ยา การเตือน และกล่องข้อความของตนโดยตรง |
