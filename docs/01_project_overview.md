# 01. ภาพรวมโครงการ

ปรับปรุง 7 กันยายน 2569 (2026-09-07) — ฉบับ scope manual ขนาดเล็ก ยังไม่ใช่หลักฐานว่าโค้ดหรือฐานข้อมูลทำครบแล้ว

ระบบคลินิกมหาวิทยาลัยและรายการเตือนแบบกรอกเอง สำหรับมินิโปรเจกต์ COE67-331 ส่งวันที่ 18 กันยายน 2569 ใช้ Next.js, React, TypeScript, Tailwind CSS และ Supabase จริงผ่าน database repository; mock ใช้สำหรับ automated tests/offline demo ไม่มีบริการอีเมลหรือ worker ใน scope

บทบาทมี 3 กลุ่มเท่านั้น: ผู้ป่วย (`patient`), แพทย์/เภสัชกร (`medical`) และเจ้าหน้าที่/แอดมิน (`staff_admin`) แต่ละบทบาทมี guarded entry page/dashboard และแยก role-specific container เมื่อข้อมูลหรือคำสั่งต่างกัน

เส้นทางหลัก: ผู้ป่วยสมัครและยืนยันอีเมล → เจ้าหน้าที่/แอดมินกรอก slot → ผู้ป่วยจอง → เจ้าหน้าที่/แอดมินอนุมัติ → แพทย์/เภสัชกรตรวจและจัดการยา → เจ้าหน้าที่/แอดมินกรอกรายการเตือน → ผู้ป่วยบันทึกผลด้วยมือ

ดูภาพรวม flow ได้ที่ [clinic-manual-process.html](clinic-manual-process.html)

| เจ้าของ | งาน | ผู้ตรวจ |
| --- | --- | --- |
| ฟีม | สมาชิก โปรไฟล์ สิทธิ์และ session | เฮิร์บ |
| ช้อป | แผนก แพทย์ ตารางและ slot | ปาย |
| ปาย | นัด คิว ผลตรวจ และรายการยา | ช้อป |
| กัญจน์ | คลังและจ่ายเต็ม | กลอง |
| กลอง | รายการเตือนแบบ manual | กัญจน์ |
| เฮิร์บ | Broadcast และ Dashboard | ฟีม |

มี Dashboard ตามบทบาททั้ง 3 และ Broadcast โดย `staff_admin` การเลื่อนนัดอัตโนมัติ งานยาค้าง การแบ่งจ่าย การกันยา email และ worker อยู่นอก scope กติกาล่าสุดอยู่ใน [08](08_system_rules_and_acceptance.md) และ [10](10_team_decisions.md)

ใช้ข้อมูลสังเคราะห์กลาง 4 แผนก แพทย์ 6 คน เภสัชกร 1 คน ผู้ป่วย 8 คน และบัญชี `staff_admin` 2 คน รวม 17 บัญชี ไม่รวม walk-in, Web Push, ลากวางปฏิทิน, กราฟขั้นสูง, การชำระเงิน, การคืนยา หรือการเชื่อมโรงพยาบาลภายนอก

## ผลลัพธ์ที่โครงการต้องสื่อให้เห็น

การสาธิตควรทำให้เห็นเส้นทางเดียวกันตั้งแต่ต้นจนจบ: บัญชีมี role ถูกต้อง, slot ถูกกรอกและมีความจุ, นัดถูกสร้างและอนุมัติ, ผลตรวจและรายการยาถูกบันทึก, การจ่ายยาสำเร็จต้องจ่ายเต็ม, รายการเตือนถูกกรอกโดย `staff_admin`, ผู้ป่วยบันทึกผลเอง และ Broadcast ถูกสร้างเมื่อกดส่ง ผลลัพธ์แต่ละช่วงต้องอ่านได้จากข้อมูลที่บันทึกไว้ ไม่ใช่จากการคำนวณอัตโนมัติ

## ขอบเขตของแต่ละบทบาท

| บทบาท | ใช้ระบบเพื่อ | สิ่งที่ต้องไม่ตีความเกิน scope |
| --- | --- | --- |
| `patient` | ดูแลข้อมูลตนเอง จองนัด อ่านผล/ยา และบันทึกผลเตือน | ไม่จัดการบัญชีผู้อื่น ไม่เข้าหน้า Dashboard รวม |
| `medical` | ทำงานตรวจรักษาหรือจัดการยา ตามนัด/งานที่รับผิดชอบ | ไม่ถือเป็นสอง role และไม่แก้งานของผู้รับผิดชอบคนอื่น |
| `staff_admin` | กรอก slot จัดการนัด บัญชี เตือน Dashboard และ Broadcast | ไม่ได้ทำให้ระบบมี automation หรือเปิด diagnosis ในข้อมูลรวม |
