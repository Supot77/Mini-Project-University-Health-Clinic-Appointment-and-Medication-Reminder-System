# 09. แผนพัฒนาและส่งต่องาน

ปรับปรุง 6 กันยายน 2569 (2026-09-06) — ทีมรับรอง normalized schema แล้ว ยังไม่รัน migration กับฐานจริง

## สถานะและสิ่งที่ต้องทำก่อนลงโค้ด

ทีมเลือกแบบแยกตารางแล้ว งาน schema รอบนี้เพิ่ม migration 03, types และ static tests แบบ additive ไม่เปลี่ยน runtime mock, seed หรือฐานจริง

1. รับรองแบบข้อมูลและสัญญาที่รองรับเลื่อนนัด แบ่งจ่าย กันยา ประวัติแก้ มื้อ งานอีเมลและ Broadcast
2. กำหนดขอบเขตธุรกรรม version/idempotency และสิทธิ์เฉพาะข้อมูล รวม session เก่าที่ต้องหมดสิทธิ์ทันที
3. กำหนดนโยบาย worker/retry/catch-up และกรณีขอบเวลาที่ยังไม่ตอบ
4. ทดสอบติดตั้งใหม่และอัปเกรดฐานทดลอง; ไม่ต้อง backfill JSON เดิมเพราะมีแต่ข้อมูลทดลอง

## สัญญาส่งต่องานที่ต้องตรึง

| ผู้ส่ง → ผู้รับ | ข้อมูล/ผลที่ต้องมี |
| --- | --- |
| ฟีม → ทุกคน | user ID, role, ประเภทผู้ป่วย, account/session validity และขอบเขตข้อมูลอ่าน |
| ช้อป → ปาย | slot ID, doctor ID, วันเวลาไทย, ความจุ, ที่กัน, closed; คำสั่งจอง/คืน/ย้ายที่ atomic |
| ปาย → กัญจน์ | record/item ID, version, ผู้ป่วย, จำนวน/หน่วย/คำสั่งยา และการแก้เฉพาะส่วนค้าง |
| กัญจน์ → กลอง/Staff | dispensing ID/item ID, จำนวนรับจริง, คำสั่งใช้ และรหัสกันซ้ำ ไม่เริ่มเตือนจากยอดค้าง |
| กัญจน์ → เฮิร์บ/Staff | ค้างพร้อมจ่ายหลังเภสัชกรยืนยันและกันแล้ว ยกเลิกค้าง/ปล่อยจำนวนพร้อมเหตุผล |
| กลอง → เฮิร์บ | dose/event ID, ผู้รับ, เวลา, เส้นตาย, email pause และสิทธิ์ส่งข้ามพักหนึ่งครั้ง |
| ทุกคน → เฮิร์บ | สูตรและหน่วยนับต้นทางที่รับรอง ขอบเขตแต่ละบทบาทและการกันคำขอซ้ำ |

คำสั่งแก้ข้อมูลต้องมีผลสำเร็จ/รหัสเหตุผลที่แสดงภาษาไทยได้ เช่น ไม่มีสิทธิ์ คิวเต็ม สต๊อกพร้อมจ่ายไม่พอ เวอร์ชันเก่า หรือทำไปแล้ว ชื่อ RPC และโครง JSON สุดท้ายยังไม่ถือว่าอนุมัติ

## ลำดับ implementation ภายหลัง

- ฟีม/หัวหน้าทีมและเจ้าของโมดูล: schema, constraints, RLS/views/RPC, migration/backfill และ types
- ช้อป/ปาย: นัด ความจุ เลื่อนนัดและการตอบ/worker พร้อมกัน; ปาย/กัญจน์: รายการใบสั่งและเวอร์ชัน
- กัญจน์: จ่ายแต่ละครั้ง กัน/ปล่อยและค้าง; กลอง: Staff ตั้งจากรับจริง ผู้ป่วยยืนยันและล็อกมื้อ
- กลอง/เฮิร์บ: งานส่งตามเวลา พัก/ส่งข้ามพัก ลิงก์กลับมื้อ; เฮิร์บ/ฟีม: Broadcast และ Dashboard แยกสิทธิ์
- ทุกคน: Catalog ตามกติกาล่าสุด สิทธิ์ตรง AC การทำงานพร้อมกัน และ SCN-01–07

## รายการที่ยังต้องหาข้อสรุป

| เรื่องที่ยังไม่ยืนยัน | ผู้เกี่ยวข้องสำหรับติดตาม | ผลที่ต้องได้ |
| --- | --- | --- |
| ความจุรอบเดิมขณะรอเลื่อน และช่วงวันของข้อเสนอ | ช้อป/ปาย | จังหวะคืนที่เดิม กฎเวลาทับ และข้อเสนอที่ถูกแทน/ถอน |
| คืนยาที่จ่ายแล้ว/แก้การจ่ายผิด/แก้วินิจฉัยหลังปิดตรวจ | ปาย/กัญจน์ | ผู้ทำ ขั้นตอนและประวัติ ไม่แก้ทับการจ่ายเดิม |
| Worker และอีเมลล้มเหลว | กลอง/เฮิร์บ/ผู้ดูแลบริการ | ความถี่ จำนวน retry ระยะตามส่งเมื่อระบบหยุด และผู้ดูแลจริง |
| เป้าหมายเดโมอีเมลจริง | ฟีม/กลอง/หัวหน้าทีม | กล่องมหาวิทยาลัยที่ทีมควบคุม; โดเมน clinic-demo.test เดิมใช้รับอีเมลจริงไม่ได้ |
| ยืนยันเวลาอดีต/กดกินล่วงหน้า/นิยามมื้อถัดไปเมื่อมียาหลายรายการ | กลอง/ปาย | เงื่อนไขขอบเวลาและกรณีชนกัน; ไม่เพิ่มการแก้เวลาเตือนหลังยืนยัน |
| หยุดรายการเตือนเมื่อแพทย์สั่งหยุดยา | ปาย/กลอง | ผู้มีสิทธิ์และการยกเลิกงานที่ยังไม่ส่ง; ทีมยืนยันการพักอีเมลแล้วแต่ไม่ได้ยืนยันขั้นตอนนี้ครบ |
| SCN-04 บล็อกตามรหัสแพ้ยา | ปาย/กัญจน์/ฟีม | คงกรณีเดิมไว้ตามที่ทีมกำหนดให้ทดสอบครบ; ยืนยันรายละเอียดรหัส/การบังคับ ไม่กล่าวอ้างว่าเป็นการตรวจแพ้ยาทางคลินิกครบถ้วน |
| สูตร Dashboard หลังเพิ่มแบ่งจ่าย/กันยา | เฮิร์บ/กัญจน์/ปาย | นิยามจำนวนใบ/รายการ ยอดคงคลังหรือยอดพร้อมจ่าย และสูตรที่รับรอง |
| รูปแบบไฟล์ส่ง ผู้รวมโค้ด ผู้ดูแลบริการสำรอง งบประมาณ และนโยบายเก็บ/ลบประวัติทั่วไป | ทุกคน | ผู้รับผิดชอบจริง ขอบเขตและวันตอบ ไม่กำหนดชื่อหรือตัวเลขแทนทีม |

## หลักฐานก่อนส่งงาน

คำสั่งที่มีใน package.json: npm run lint, npm run test, npm run build ยังไม่มี script typecheck ให้ใช้เครื่องมือในโครงการผ่าน npx --no-install tsc --noEmit เมื่อถึงรอบตรวจโค้ด หรือเพิ่ม script ในงาน implementation ที่อนุญาตแล้ว

ใช้แบบบันทึกผลใน [08](08_system_rules_and_acceptance.md) ไม่ทำเครื่องหมายผ่านจากแค่มีเอกสาร ต้องมีผลจริง ก่อนรวม main ผ่าน gates/กรณีหลัก และก่อนนำเสนอผ่าน SCN ทั้ง 7 พร้อมอีเมลจริง
